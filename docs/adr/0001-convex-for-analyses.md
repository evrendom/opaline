# Convex stores analyses

Saved analyses (question, steps, queries with exact results, findings, final answer) live in Convex, not in Postgres or ClickHouse. Convex was chosen because team analyses will become multiplayer (people watching and challenging an analysis as it forms) and because reuse needs vector search over questions and step sub-questions; Convex provides both, so we avoid building on Postgres now and migrating later. Postgres with pgvector was the alternative: simpler deletion (foreign-key cascade) and auth (better-auth already there), but no reactive queries.

## Considered Options

- Postgres + pgvector behind a storage module, migrating to Convex when multiplayer ships.
- ClickHouse: rejected; analyses are point lookups and documents, not analytics.

## Consequences

- Only our API writes to Convex (server key); agents never talk to it directly. Owner and workspace checks are enforced inside the Convex functions.
- Deleting a workspace deletes all its analyses. Deleting an account deletes its own analyses and, by any author in any workspace (amended by ADR 0005 and on 2026-10-12):
  - every analysis with a step or stored result that returned text from the account's sessions: prompt heads, quotes, excerpts, snippets, commands, paths, whatever the tool (`read`, `find`, `sql`, or results opened through `answers`). A result returns text unless every value it returned is known to be a number, a time or an id; anything else counts as text, and results stored before this rule count as text. A result that read several members' sessions and returned text is treated as quoting each of them;
  - every analysis whose finding cites one of the account's runs: a finding on a step whose result names one of its sessions (the finding impact provenance in `analysis_finding_runs` follows the same rule through `quoted_owners`);
  - nothing is redacted line by line inside a kept analysis.

  A result that returned only numbers and ids over the account's sessions (counted them, usually among others') is removed instead: marked `removed`, its output gone, the account dropped from the members it read, and the analysis stays. Its query stays so it can be rerun, except arguments that may carry text copied from a transcript, which go with the result: an SQL statement with any string literal, quoted name or comment, and `find` arguments other than enums, dates, numbers and ids (such as a command prefix); the step label is rebuilt without them. Stored `sql` results in Postgres follow the same rule: one whose shown rows returned text is deleted, one that only counted is removed, its title kept and its SQL emptied when it carries text. Everything runs in the durable purge and again in its follow-up pass, which catches analyses that read the account's sessions meanwhile, so a deleted account's session content is gone within the purge's deadline, well inside the privacy policy's 7 days. Each stored query therefore records the sessions (and transcript generations) it read, every member whose sessions it could read, and whether its result only counted. A re-uploaded session deletes nothing: queries that read an older generation are flagged as changed when opened.
- Retention: an analysis (question, steps, findings, final answer) stays until its author or workspace deletes it; exact query results expire after 90 days (a year for analyses that are shared or pinned), while their arguments stay so they can be rerun. Until it is saved, an analysis is a private draft that no one can open, deleted 7 days after it was started; a saved analysis is never changed, and a revision is a new analysis linked with `updates`.
- Region is open: the EU region (AWS eu-west-1) is intended but not yet available to us. Development runs on a local or US deployment with our own data only; the region, a DPA and a subprocessor review are decided before customer data is stored. EU region means data location, not EU jurisdiction.
- Embeddings come from OpenAI `text-embedding-3-small`, called by our backend. For saved analyses, only the question title and topic words are embedded, when the analysis is saved, never its query results. Session text is embedded with the same model when a session is uploaded, so sessions can be searched by meaning (amended 2026-10-12; see `docs/retro-architecture.md`).
- Restricting a shared analysis's results to admins and the session's owner applies only to workspaces with the own-sessions-only option on, which is off (amended by ADR 0004).
- Self-hosted servers keep analyses in their own Postgres instead (amended 2026-11-08): the same records, rules and retention behind the same store interface, with embeddings in a `bytea` column ranked by the API, since a single team's analyses fit in memory and pgvector is not assumed. Production keeps Convex.
